# Read and edit XFA forms with bold and italic text

PDF.js 6.3.289 can fail to open an XFA form when its rich text contains `<b>` or `<i>`. This example supplies a small source patch, a version-checked worker repair, and synthetic two-page forms for checking loading, appearance and repeated editing.

[Download the complete example](../../downloads/xfa-rich-text-v0.1.0.zip?raw=true). Python 3.10+ prepares the official runtime; a current Chrome browser runs the viewer and checks. No npm installation is needed.

## Try it

Extract the ZIP, enter its directory, then run:

```sh
python3 prepare.py
python3 -m http.server 8000 --bind 127.0.0.1
```

On Windows, `py -3` can be used instead of `python3`. Open <http://127.0.0.1:8000/>. Preparation downloads PDF.js 6.3.289 from npm, verifies its SHA-512 integrity and the original workers' SHA-256 hashes, and creates separate `pdf.worker.xfa.mjs` files. The original workers are retained. Preparation needs an internet connection; the viewer uses local assets and does not upload documents.

1. Open **Bold with nested italic**. Both pages should load, with bold and italic text on page one.
2. Change **Project note**, then choose **Save and reopen**. Check the saved value and the unchanged `REF-204` reference.
3. Change the note again and save again. Both the second value and page two should remain. The reference stays read-only.
4. Choose **Run checks** for all nine text examples, two save/reopen cycles and the disabled-XFA setting.
5. Follow **Compare the official worker**. The plain-text control loads; examples containing `<b>` or `<i>` reproduce the failure.

The [nested sample PDF](samples/nested.pdf) and [plain control](samples/plain.pdf) are generated by [fixtures.mjs](fixtures.mjs). They contain no scripts, external resources or submission actions. Use **Download current PDF** to save a copy including current field edits.

## What changes

The problem and missing `measure.pushFont` call were identified by [vsmeenaravi in PDF.js #22023](https://github.com/mozilla/pdf.js/issues/22023). This implementation uses the existing shared style/measurement path instead of adding the suggested missing method:

- Give `B` a default `font-weight:bold` and `I` a default `font-style:italic`.
- Remove their special `$pushGlyphs` overrides, so the shared implementation handles font state, margins, line height and nested content.
- Prepend defaults before document-provided styles, preserving explicit `font-weight:normal` and `font-style:normal` overrides.

This also emits inline styles for the viewer. Merely restoring the missing method leaves the tags visually normal under the standard viewer's inherited-style reset.

For a PDF.js source checkout at **v6.3.289**, apply [pdfjs-6.3.289.patch](pdfjs-6.3.289.patch):

```sh
git apply --check /path/to/pdfjs-6.3.289.patch
git apply /path/to/pdfjs-6.3.289.patch
```

Then follow PDF.js's own build and test instructions. For an existing application using the prepared distribution, use the matching runtime and repaired worker together:

```js
import * as pdfjsLib from './runtime/build/pdf.mjs';
pdfjsLib.GlobalWorkerOptions.workerSrc = new URL(
  './runtime/build/pdf.worker.xfa.mjs', import.meta.url
).href;
const loadingTask = pdfjsLib.getDocument({
  url: './samples/nested.pdf',
  enableXfa: true,
  standardFontDataUrl: './runtime/standard_fonts/',
});
```

The complete viewer, form editing and save/reopen wiring is in [demo.mjs](demo.mjs). XFA remains opt-in. Keep the main library and worker on the same version; do not apply this exact-version repair to another release without checking its source and results.

## Verification and limits

On 2026-09-28, the included checks produced **11/11 passes** with the repaired modern worker in Chrome and with the legacy worker in Node.js. The unmodified workers produced **2/11 passes**: plain text and the disabled-XFA control. The other nine failed, including actual form loading and editing. Removing the bold default from the final repair caused six checks to fail.

The checks assert actual two-page content, existing field values, non-interactive settings, emitted styles and layout agreement with equivalent styled spans. They perform two real `saveDocument()` / reopen cycles. Software-operated Chrome checks additionally verified rendered bold/italic styles, explicit normal overrides, the read-only reference and two edits through the viewer's controls. Details are in [verification.json](verification.json).

These are synthetic regression documents, not the reporter's original file. This is an independent, temporary example; it has not been merged upstream or confirmed by the reporter. The full upstream PDF.js suite, Firefox, Safari, Windows execution, printing and arbitrary production documents were not tested. Node.js verification used canvas DOM shims and the legacy distribution. The fixture intentionally uses standard-font fallback; it does not establish compatibility with every embedded font.
